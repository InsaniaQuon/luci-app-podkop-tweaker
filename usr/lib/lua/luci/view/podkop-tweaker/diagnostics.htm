External DNS Observation

Independent manual browser test via bash.ws; Run All Diagnostics does not include it. It identifies recursive DNS resolvers observed for this run, not a guarantee that DNS cannot leak.

How to read results

When to run: There is no required order and this is not a prerequisite for other tests. For troubleshooting, start with Podkop Diagnostics, then use Observe Browser DNS to inspect the resolvers observed from this browser.

The router creates a test ID, this browser attempts six unique HTTPS probes, and bash.ws reports the recursive resolvers seen by its DNS observer. Browser DoH and Podkop split-routing/FakeIP affect the measured path; other applications and LAN devices can use different paths.

Observed Resolver IP / ASN
Source IP addresses of recursive DNS resolvers observed externally. These are not the resolved addresses of the test websites. A resolver's outgoing IP can differ from its configured endpoint, such as 1.1.1.1, and multiple IPs can belong to the same provider. ASN identifies the network that owns an address.
Country
Optional IP geolocation supplied by the provider. A different country or ASN alone is not proof of a DNS leak.
Provider Control Request IP (router)
The public IP seen for the provider API request made from the router. Its route may be direct or proxied. It is not a measurement of the browser's public IP, and it does not need to match the observed resolver IPs.
Detail
The observation summary, or the reason why results could not be collected. Interpret the resolver list against your intended DNS and routing policy.
OBSERVATIONS COLLECTED
At least one resolver was observed. This means data was collected, not that all probes succeeded or that DNS leaks are absent.
INCONCLUSIVE / No observations
No sufficient observations were received, or a provider/network/request error occurred. This confirms neither a leak nor the absence of leaks.

Run Log fields:

provider / id
The observation service and its identifier for this test run.
scope: current_browser
The HTTPS probes originate from the browser that opened this page.
control_request_scope: router
The provider API/control request originates from the router.
probes_completed
The number of browser probes that reported a load or an error event. A value of 6 does not mean six successful requests, DNS answers or different resolvers.
complete: true
At least one resolver observation was returned. An empty resolver list is inconclusive.
OK / ERROR
For this test, OK means observations were collected; ERROR means the observation could not be completed. Neither status is an automatic verdict about DNS leaks.

Keeping the report: Each new test or Run All Diagnostics clears the previous Run Log. Use Download Log (JSON) before starting another run if you want to keep these observations. A page refresh keeps the current log.
